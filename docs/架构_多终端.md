# S2Arm 多终端架构与目录方案（10-21 维护者定稿，维护者 授权）

目标终端（维护者 10-21）：**iOS（iPhone + iPad）、macOS、安卓、鸿蒙**。原则：一份平台无关的核心，各终端只写「外壳」和「平台接口实现」；渲染按图形 API 分后端（Metal：iOS / macOS；Vulkan：安卓 / 鸿蒙）。新终端 = 新增一个外壳目录 + 一份平台接口实现，不改核心。

## 1. 分层

| 层 | 内容 | 跨终端 |
|---|---|---|
| 核心·原生执行 | NSO 装载、svc、线程 / 栈、地址窗口逻辑、确定性、自检、改写器 | 全部共用，只调平台接口 |
| 核心·系统层 | C# 服务层（Ryujinx HLE + 我方补丁）、NativeAOT 组装 | 全部共用 |
| 核心·显卡模拟 | Ryujinx GPU、渲染循环、写跟踪、宽屏改写（10-25 起苹果端主路径为直连，显卡模拟只作兜底，见 方案_快速通用模式.md；安卓只走直连，与苹果端对齐：不给模式或给 auto 都按直连起，直连出问题不回落到显卡模拟，通用后端先保留编译、不再修） | 全部共用 |
| 渲染后端 | GAL 实现：Metal（iOS / macOS）、Vulkan（安卓 / 鸿蒙） | 按图形 API |
| 平台接口实现 | 虚拟内存重映射、线程槽 / QoS、锁、时钟、崩溃现场、能耗探针 | 苹果一份、Linux 系（安卓 / 鸿蒙）一份，各终端可覆盖 |
| 终端外壳 | 入口、窗口 / 出图层、触屏虚拟手柄、生命周期、打包签名 | 每个终端一份 |
| 出包流水线 | 公共阶段（解包、改写、着色器、资源包）+ 终端阶段（ipa / app / apk / hap） | 公共 + 按终端 |

## 3. 平台接口（platform/plat.h）

取代「把苹果接口假装出来」的替身头（PR #1 的 darwin_shim.h 思路）。核心代码不再直接调 mach / os_unfair_lock / tpidrro_el0，改调：

- 内存：`plat_vm_alias`（别名映射，苹果 vm_remap / Linux mremap(old_size=0)）、`plat_vm_reserve`、`plat_page_size`
- 线程：`plat_tsd_base` / `plat_tsd_offset`（苹果 tpidrro_el0；musl / bionic 起局探测）、`plat_thread_qos`、`plat_thread_suspend`（不支持的平台返回失败，调用方已有退路）
- 同步与时钟：`plat_lock_*`、`plat_now_ns`
- 诊断：`plat_crash_context`、`plat_energy_snap`（不支持的平台返回 0 行）
- 缺页 / 陷阱分发（原生层线 10-21 补）：`plat_fault_install`、`plat_ucontext_pc` / `plat_ucontext_regs`——写跟踪、门控陷阱、崩溃处理都靠信号；macOS 上 mprotect 触发 SIGBUS、Linux 是 SIGSEGV，mcontext 布局也不同（crash.c、track.c、det.c、svc_mem.c）
- 宿主页大小 `plat_page_size` 要连带清掉核心里硬编码的 16 KB（loader.c 8 处、thread.c 6、det.c 3、svc_mem.c 2、layout.c 2、widen.c 1；track.c 已是运行时）
- 地址区查询 `plat_vm_query`（苹果 vm_region_64：低区余量、窗口探测、写跟踪保护核对）
- 内嵌模块段 `plat_module_image`（苹果 getsectiondata：iOS 改写产物编在 __TEXT 里）
- 代码页映射 `plat_code_map`（苹果 MAP_JIT / 写保护切换；Linux mprotect PROT_EXEC）
- 内存实占 `plat_mem_footprint`（苹果 proc_pid_rusage / task_info；心跳与 C# MemDiag 共用，C# 侧也走 plat 导出，不各自判 OperatingSystem）
- 出包：改写器 `S2A_TARGET` 必须进改写产物的缓存键（pack/stage_rewrite.sh），或产物按目标平台分目录，否则不同平台的改写产物会互相顶替

现有苹果依赖分布（10-21 统计，次数）：thread.c 25、energy.c 25、vawin.c 18、det.c 18、tdump.c 17、loader.c 10、svc_mem.c 8，其余 ≤6。这些都是原生层线的活。

## 4. 迁移分三步（不停工）

1. **搬目录（一次机械提交）**：只 `git mv` + 改构建脚本 / 门禁 / 出包路径，不改代码逻辑；在列车空闲时用 `train.sh pause` 停取新批后合入。各线分支用 git 改名识别直接 rebase；附「旧路径 → 新路径」对照表。执行：测试出包线（构建、门禁、出包、列车都归它），各线先审对照表。
2. **抽平台接口**：原生层线把 §3 列的直接调用改成 `plat_*`，苹果实现落 platform/apple，产物逐字节不变（iOS / Mac 局对拍）。之后 PR #1 改为实现 launchers/linux + platforms/ohos，去掉替身头。
3. **扩终端**：iPad（同一个 iOS 包，设备族加 2，出图层与触屏布局按屏幕比例自适应）、macOS 产品外壳、安卓外壳（Vulkan 后端与鸿蒙共用）。
   安卓扩终端前要解决的三条（10-22 原生层线评估 PR #7 / #8 的发现，当时不做）：
   - **改写器补丁块不借用 sp 下方**：苹果 ARM64 ABI 保证 sp 下方 128 字节红区，信号不会写进去，现有补丁块借用 sp 下方是安全的；Linux AArch64 没有红区。#7 让客体线程的信号走备用栈，但 bionic 会把它内部用的 `__SIGRTMIN+1..8` 从屏蔽集里去掉，这些信号的处理函数不一定带 `SA_ONSTACK`，在客体代码里送达就会写进 sp 下方、盖掉补丁块的临时数据。做法：`S2A_TARGET=android` 的补丁块先下移 sp 再用（或整体改用线程私有暂存区），苹果目标产物逐字节不变（照 PR #5 的九款真模块对拍）。
   - ~~**.NET 加密在 bionic 上 abort**~~ **已由 PR #9 解决**（main ebc70d484）：App 自带 NDK 编的 OpenSSL 3.5.9（源码 SHA-256 钉死，只在安卓构建时用），.NET 的加密垫片按安卓路径加载 libssl.so；真机随机数 / SHA-256 / AES 均按已知答案通过。
   - ~~**`NativeLibrary.GetMainProgramHandle` 查不到导出**~~ **已由 PR #10 解决**（main dfc8b4502）：服务层 NativeAOT 静态链进宿主 .so，s2a_native 按 DirectPInvoke 链接期绑定（同 iOS）；运行时自带的 libunwind 符号改名避开 NDK 的。原生核心接上之前由 s2a_native_stub.c 占位；仍按名字查导出的几处（InputPump `s2a_vpad_read`、Native.cs 确定性档 / 客体时钟）接核心时要改成函数指针。

## 4.1 分发渠道结论（10-29，情报研读后存档）

- **iOS 替代商店不适合当前出包模式。** 日本（iOS 26.2 起）、巴西（26.5 起）已开放替代商店，欧盟 10-01 起换成统一条款；但商店分发的必须是开发者签好的成品，S2Arm 是玩家用自己的游戏在本机出包，游戏代码不能进商店。替代商店最多能分发一个不含游戏代码的外壳，现阶段仍只走自签 / 侧载（推断，依据 `docs/研究/情报/20261028_方向三四增量跟踪.md` 第 15–19 行）。
- **安卓按游戏出 APK 走侧载**：2027 年开发者验证全球化后，已认证设备上只剩 adb、有限分发（20 台）、高级流程三条路，细节见 `android/README.md`「Distribution constraints」。

## 6. 外部 PR 规则

- 外部 PR 不直接合 main：对口线拉分支到工作树、合 main、跑整套门禁、`train.sh enqueue`。
- 跑门禁前先读 diff，查危险写法（进程组 kill、kill -1、rm -rf 共享目录、联网、改门禁 / 列车规则）。
- Ryujinx 补丁名带生成时刻（`compat/patch_new.sh` 生成），series 与改动清单 merge=union，并行加补丁不撞号、不冲突。

## 7. Ryujinx 公用部分的平台边界（10-30 维护者 批，平台 adapter 边界设计 P0–P7）
一份 Ryujinx（compat/tree，一条补丁链），一份共享宿主（services/S2A.Services）。平台差异只能通过**登记进来的接口实现**进入。边界由全模块盘点推出：`tools/platform_scan.py` 扫 104 个模块，65 个纯共用不动、23 个纯共用但我方改过、4 个只有上游平台判断、12 个有我方平台专属代码要迁。设计全文与 P 阶段见共享笔记「原生层_平台adapter边界设计_1030」，各面的接口签名见 #1069–#1077。
1. 共享代码（compat/tree、services/S2A.Services）**不新增** `OperatingSystem.IsXxx` / `RuntimeInformation` 平台判断、平台库导入（libSystem、CoreFoundation、VideoToolbox、android、aaudio……）、共享代码直接引用某平台实现类型，以及 `NativeLibrary.GetExport` 按名找导出。上游 Ryujinx 原有的平台判断保留。
2. 平台实现只放 `platforms/<平台>/`，由平台装配（苹果：现在是 services/aot/Compose.cs，迁往 platform/apple/cs/；安卓：AndroidGameRuntime）在 Host.Boot 之前登记进 `Exports`、`S2AHooks`、`InputPump`、`ControllerFeedback`、`S2AVideoDecoders`、`S2AHostFileSystem`、`S2APlatform` 等接缝。时钟、调度、日志这类两端都有的能力走 `platform/plat.h`。
3. 缺省值不偏向任何平台：接口没登记就用哑实现，并报一行红（每个接口写明哑实现的行为）。
4. compat/tree 的补丁只加**中性接缝**（钩子、工厂、能力位），不加某个平台的实现。
5. **门禁「只减不增」**：`tests/platform_scan_test.sh` 用 `tools/platform_scan.py --gate` 比较本树与 origin/main 的「我方平台行 / 按名找导出」。逐行比较（按类别、文件、行文本计次数），多出来就报红并点名那一行。确需例外，在那一行写 `// 平台例外：<理由>`，不设公用白名单，免得又造出一个人人都改的清单。
6. 列车按影响范围拆批：只动 `platforms/<平台>/` 的分支，只跑那个平台的门禁。


### 实验预算启动接口

原生布局使用内部字节额度提供方 s2a_app_pool_process_limit()。runtime/src/layout.c 提供返回 UINT64_MAX 的弱默认实现，ios/guest_budget.m 提供查询内核的强实现。接口在 UIKit 初始化前可调用，由共用布局冻结一次结果。未显式启用 auto 时采用原生或手动预算，显式 auto 遇到不可用提供方时报告失败。接口的单位、有效零值、未知值和验证边界见 [实验性客体内存预算](实验_客体内存预算.md)。
